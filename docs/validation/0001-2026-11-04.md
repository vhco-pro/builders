# Ubuntu image validation, 2026-11-04

These are the implementing agent's observed results, not independent reviewer execution or formal
feature acceptance. The owner inspected the candidate before authorizing its commit and PR update.

## Environment and commands

- Packer 1.16.2, Proxmox plugin 1.2.4, QEMU plugin 1.1.8 and Proxmox VE 9.1.7.
- Ubuntu noble amd64 cloud-image inputs. The replacement build environment was a fresh Ubuntu 24.04
  container using the direct libguestfs backend, a readable host kernel and an explicit DHCP client.
- The Proxmox server has two Xeon E5-2620 processors with AES and AVX. Native builds used a temporary
  VM-scoped API identity. The controlled self-signed test endpoint used the explicit TLS-verification
  opt-out; production certificate trust was not established by this test.
- `make init` installed both pinned plugins into an empty plugin directory.
- `make check` passed Packer formatting/validation, ShellCheck and all 26 local regression tests in
  a disposable tool environment with the declared dependencies. A host attempt lacked ShellCheck;
  the subsequent complete container run passed.

## Bootstrap and recovery

The off-node preparer produced a checksummed base bundle with the guest agent installed and identity
reset. A separate non-root SSH-only client imported that bundle using the committed transport scripts,
without local Packer or libguestfs. Repeating an occupied ID was refused. Corrupt and partial bundles,
unsafe staging replies, upload failures, remote ID races and shrinking are covered by local fixtures;
these failure cases were not all repeated against live Proxmox.

No Packer or libguestfs packages were installed on the hypervisor. The tests required independent
Proxmox access and upstream reachability. They do not establish a full Fedora restoration or an
already-configured off-host backup destination.

## Native image and fresh clones

`packer build -only='proxmox-clone.ubuntu' .` completed in 2 minutes 56 seconds with the `host` CPU
default. The golden template had `template: 1`, a cloud-init drive and no retained build cloud-init
credentials. Two fresh full clones inherited `cpu: host`, exposed AES and AVX, accepted their separate
consumer users and SSH keys, and reported different machine IDs and SSH host keys. Both retained a
locked, keyless default Ubuntu account and disabled SSH password authentication.

Read-only disk inspection confirmed generic hostname, empty machine-id, no generated netplan, seed,
build keys, key backups or SSH policy override, and the expected baseline packages and OS settings.
The four owned disposable resources and temporary API identities were removed. Configuration hashes
and power states for all seven original guests matched the fresh preflight baseline.

The final validation guard was tightened after the live build to reject surrounding whitespace. Only
its condition and error message changed: the valid `host` default, CPU wiring and guest scripts are
identical. Complete local checks passed again. Exact local commands validated
`-var 'proxmox_cpu_type=x86-64-v2-AES'` and rejected empty and whitespace-padded model names.
This proves local configuration validation, not target-node support for the alternate model.

## Portable image

The portable KVM build produced qcow2 and raw disks with a 10 GiB virtual size and identical logical
contents. Offline sealing inspection and two independently initialized fresh boots passed; consumer
keys worked, password authentication was disabled, and machine IDs and host keys differed.

The later native task timeout and CPU settings do not alter the QEMU source, shared provisioners or
raw exporter. Source comparisons verified that boundary. The portable image was not rebuilt for the
native-only CPU setting or the stricter valid-input guard.

## Evidence boundaries

The task retained logs, source manifests, failed attempts, clone observations and cleanup audits in
its private review artifacts. Paths used during execution were `/tmp/builders-offnode/` and
`/tmp/builders-hostcpu-20261104/`; these are local artifacts rather than public downloadable fixtures.
This committed summary makes the observations durable, but cannot substitute for an independent run.

ARM/HVF, other storage backends, a full Fedora restoration, off-host backup provisioning, alternate
CPU models on real hardware and a complete automated CI image-build harness remain unverified or
separate work. No production guest was changed by these tests.
