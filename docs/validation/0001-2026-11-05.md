## Limits and cleanup

All eight final instances passed fresh-user shell/tool and supplied-key checks. Across the complete
matrix, machine IDs, SSH host keys, DHCP client identities and hostnames were distinct. Each pair
rejected the other instance's key. Both default outputs passed permissive authentication controls
followed by baseline enforcement, and all four default instances ran the exact update command under
the cron environment. Both custom outputs retained their selected shell/MOTD setup with no PDS-managed
SSH policy or update job.

Every deployment phase removed its two owned instances and verified seed/snippet cleanup. The final
cleanup removed the seven retained build/base resources, their volumes, the approved snippet-only
storage and leftover owned export directories. No task API identity or owned volume remains. All seven
original guests' configuration hashes and power states match the preflight snapshot. Original storage
settings are semantically unchanged: Proxmox returned the same content sets in different orders, and
reconstructing those orders reproduced both original hashes before cleanup proceeded.

The failed custom-archive download is retained separately. A bounded-buffer retry recovered the
complete archive and verified the checksum against the runner before deployment. The first runner
timed out waiting without creating portable guests. Earlier attempts also exposed the SSH journal
observer's identity-reset gap and an inactive owned template volume during export; their failed logs
remain separate from the corrected final builds. Preliminary clone results do not substitute for the
final eight-instance matrix.
